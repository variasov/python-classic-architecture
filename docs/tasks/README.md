# Задачи демо-проекта «Библиотека»

Спецификация `docs/demo-spec.md` нарезана на вертикальные задачи. Каждая задача - одна
бизнес-функция end-to-end: домен → app → хранилище → HTTP → композит → тесты всех слоёв.
После задачи фичу можно проверить целиком (e2e-тестом через HTTP на тестовой БД), не дописывая
остальные функции слоя.

Источник требований - спецификация: задача указывает, какие её разделы реализовать и какие
файлы появятся, но не повторяет требования. Если задача и спецификация расходятся - права спецификация.

## Правила для всех задач

- Перед задачей читай только скиллы, перечисленные в ней. Справки `classic-*` - перед первым
  использованием библиотеки. `references/testing.md` скилла - когда пишешь тесты этого слоя.
- Код предыдущих задач не переписывается без причины. Расширять общие файлы (`0001.init.sql`,
  `DDL.sql`, `create_app`, композит, `conftest.py`) - нормально: миграции ещё не выпущены.
- Миграции: таблицы задач 00-08 и 11 добавляются в `0001.init.sql`, таблица `notifications` - в
  `0002.add_notifications.sql` (задача 09). `sql/schema/DDL.sql` актуализируется вместе с миграцией.
- Тесты пишутся в той же задаче, что и код, для каждого затронутого слоя: unit домена и app,
  адаптеры (БД, HTTP, интеграция), e2e композита.

## Готово (для каждой задачи)

- Реализовано всё из раздела «Сделать», тесты из «Критериев приёмки» есть и зелёные.
- Зелёные проверки по всему проекту (не только по новым файлам):
  `pytest -q`, `ruff check src tests`, `ruff format --check src tests`, `pyright`, `vulture`.
- Ранее сделанные задачи не сломаны.
