# Python SQL DB adapter in "Classic" Architecture 

## Описание

В этом навыке описывается адаптер к SQL DB для приложений на Python,
соответствующих шаблону "Классической" архитектуры.

## Когда использовать
- Во время разработки новых фич в Python-приложении с "Классической" архитектурой, требующих доступа к SQL DB.

## Instructions
- Если внутренняя БД одна, пакет должен называться db. Если БД несколько, то названия должны соответствовать назначению БД.
- В пакете должна быть директория sql, в ней должны быть директории schema, migrations и templates.
- В sql/schema размещаются .sql файлы, содержащие DDL-запросы, описывающие целевое состояние БД.
- В sql/migrations размещаются файлы миграций, так же содержащие DDL, но отражающие уже историю изменний БД.
- Для применения/отката миграция используется Python-пакет classic-migrations.
- В дирекории sql/queries размещаются шаблоны запросов.
- Для работы с SQL-запросами в Python используется classic-db-tools + драйвер для БД.
- Для маппинга результатов запроса используй Entity и Value из classic-db-tools.
- Статические запросы предпочтительнее, чем динамические.
- Динамические запросы предпочтительны, когда у запроса меняется форма в зависимости от входных параметров,
  например, добавляются условия в WHERE, добавляются JOIN, меняется ORDER BY и т.д.
- В пакете так же размещается файл settings.py, в котором содержится класс, читающий переменные окружения и предоставляющий настройки для адаптера. Для настроек используется pydantic-settings.
