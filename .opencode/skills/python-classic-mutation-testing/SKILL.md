# Mutation Testing in "Classic" Architecture

## Описание
В этом навыке описывается мутационное тестирование - проверка качества unit-тестов
домена и слоя app. Инструмент - `mutmut` (3.x). Общие правила тестирования -
в `python-classic-architecture` и в `references/testing.md` навыков слоёв.

Мутационное тестирование отвечает на вопрос, который не могут проверить
pytest и coverage: убивают ли тесты реальные изменения кода. Coverage показывает,
какие строки выполнились, мутации - заметил ли тест подмену логики.

## Когда использовать
- После того как unit-тесты домена и app зелёные и линтеры чистые.
- При работе над фичей - когда фича в целом готова: код написан, тесты написаны,
  тесты зелёные. Не по ходу каждого сохранения файла.
- Перед релизом - как финальную проверку качества тестов.

## Принцип
- Мутируется только слой `app/`: домен внутри app, команды, запросы, роли.
  Это основание пирамиды тестирования: быстрые unit-тесты без БД и сети.
- Адаптеры и композит не мутируются: их тесты требуют БД и stub-серверов,
  прогон мутантов занял бы часы, а логику эти слои не содержат.
- Мутанты гоняются только против `tests/unit` - быстрый прогон (секунды).
- Целевой результат: **0 survived**. Убитыми считаются также ⏰ timeout
  (мутант сломал код бесконечным циклом) и 🧙 caught by type check
  (мутант сломал типы, см. "Отсев мутантов через type checker").

## Инструмент и окружение
- `mutmut` ставится в dev-зависимости проекта.
- На Windows mutmut не работает нативно: запускать в WSL
  (`wsl -e bash -c "..."`), путь к проекту - через `wslpath` или `/mnt/c/...`.
- Если в WSL нет системного pip/ensurepip, окружение создаётся через `uv`:
  `uv venv .venv-wsl` + `uv pip install -e . mutmut pytest` и остальные
  dev-зависимости, нужные unit-тестам. Имя `.venv-wsl` - чтобы Linux-окружение
  не пересекалось с платформенным `.venv` того же репозитория.
- mutmut пишет кириллицу в WSL-консоль: для читаемых логов запускать с
  `PYTHONIOENCODING=utf-8`.

## Конфигурация
В `pyproject.toml`:
```toml
[tool.mutmut]
source_paths = ["src"]
only_mutate = ["src/<package>/app/*"]
pytest_add_cli_args = ["tests/unit", "-q", "-p", "no:cacheprovider"]
use_git_change_detection = false
```
- `source_paths = ["src"]` - весь каталог с пакетом, не только мутируемая часть:
  mutmut собирает mutants-копию проекта, ему нужны все модули для импорта.
- `only_mutate` - фильтр того, что реально мутируется (слой `app/`).
- `pytest_add_cli_args` - какие тесты гонять против мутантов. Только `tests/unit`.
- `use_git_change_detection = false` - чтобы mutmut не требовал git-репозиторий
  и не мутировал только изменённые файлы.
- `paths_to_mutate` и `tests_dir` - устаревшие ключи mutmut 2.x, не использовать.
  В 3.x имена именно такие, как выше.

## Запуск и чтение результатов
```bash
python -m mutmut run                     # прогон
python -m mutmut results                 # сводка: killed / survived
python -m mutmut show <mutant_name>      # diff конкретного выжившего мутанта
python -m mutmut browse                  # интерактивный просмотр
```
- Прогон пишет mutants в каталог `mutants/` - он в `.gitignore`.
- Сводка в конце прогона: 🎉 killed (убит), 🧙 caught by type check (убит
  type checker-ом), ⏰ timeout (убит по таймауту), 🙁 survived (выжил),
  🫥 no tests, 🤔 suspicious, 🔇 skipped.
- Работать по циклу: прогон → список survived → тест против каждого → повтор.

## Инкрементальность прогонов
- mutmut кэширует вердикты в `mutants/<файл>.meta`, ключ - хэш функции.
  Повторный `mutmut run` перепроверяет только мутантов новых и изменённых
  функций, вердикты остальных стоят (в выводе это выглядит как
  `0.00 mutations/second` - гонять нечего, всё из кэша).
- Поэтому во время работы над фичей мутируются фактически только изменённые
  и новые файлы: их функции пере-хэшируются, остальные берутся из кэша.
  Полный прогон с нуля - только при смене конфига mutmut или удалении `mutants/`.
- `mutants/` - это кэш прогресса, а не мусор: не удалять между прогонами
  (в `.gitignore` - да, но не чистить).
- Точечный перезапуск конкретных мутантов (игнорируя кэш):
  `python -m mutmut run <mutant_name> [<mutant_name>...]`.

## Отсев мутантов через type checker
`type_check_command` гоняет type checker один раз по всей mutants-копии до
запуска тестов. Мутанты, в копии которых checker нашёл ошибку, получают вердикт
🧙 `caught by type check` без запуска тестов - и считаются убитыми. Доля
отсеянных зависит от проекта; на демо - больше половины.

Рабочая конфигурация (pyright):
```toml
# pyproject.toml, [tool.mutmut]
type_check_command = ["../.venv-wsl/bin/pyright", "--outputjson", "--pythonpath", "../.venv-wsl/bin/python", "-p", "../.pyright-mutmut.toml"]
```
```toml
# .pyright-mutmut.toml - отдельный смягчённый конфиг, НЕ боевой [tool.pyright]
[tool.pyright]
include = ["mutants/src"]
exclude = ["**/__pycache__", "mutants/src/*/composites"]
pythonVersion = "3.10"
typeCheckingMode = "standard"
reportMissingTypeStubs = "none"
reportUnknownMemberType = "none"
reportUnknownArgumentType = "none"
reportUnknownParameterType = "none"
reportUnknownVariableType = "none"
reportUntypedFunctionDecorator = "none"
reportMissingImports = "none"
reportOptionalMemberAccess = "none"
extraPaths = ["mutants/src"]
```

Подводные камни (симптом → причина → лечение):
- **cwd команды - `mutants/`.** mutmut запускает type checker из каталога
  mutants/, поэтому пути начинаются с `../`. Команда `.venv-wsl/bin/pyright`
  без `../` падает с FileNotFoundError.
- **`--pythonpath` обязателен**: в mutants/ нет venv, без него pyright не
  резолвит импорты и валится тысячами ошибок.
- **Отдельный конфиг, не боевой.** Боевой strict-конфиг репортит шум
  trampoline-кода mutmut (unknown-типы декораторов и импортов), и mutmut падает
  с "Could not find mutant for type error" - он умеет приписывать диагностику
  только мутантным копиям методов (`xǁ...ǁ...__mutmut_N`), а не коду рядом.
- **`reportOptionalMemberAccess = "none"` - критично.** Мутанты в `__init__`
  (например `self.books = None`) загрязняют выведенный тип атрибута на весь
  класс: `"get_by_id" is not a known attribute of "None"` всплывает в исходных
  методах, неприписываемых мутанту - падение. Это главный источник краша
  при включении отсева. Если mutmut всё же падает с "Could not find mutant
  for type error" - правило из текста ошибки добавить в этот конфиг как "none".
- **include ограничен мутируемым слоем** (composites исключён): диагностика
  в немутированных файлах тоже роняет прогон.
- pyright ставится в то же окружение, что и mutmut (в WSL - тот же venv).

## Проверка цели после прогона
`mutmut results` без флагов печатает всё, что не "killed", включая 🧙. Проверка:
```bash
python -m mutmut results --all true | grep -c ': killed'   # ожидание: total - 🧙
python -m mutmut results | grep -v 'caught by type check'  # ожидание: пусто
```
Цель - 0 survived, 0 not checked, 0 suspicious.

## Работа с выжившими мутантами
На каждый выживший мутант добавляется или улучшается тест, который его убивает.
Паттерны, доказавшие эффективность (в порядке предпочтения):

1. **Проверка полей доменных ошибок.** Мутант `raise LoanNotFound(id=None)`
   убивается проверкой поля: это часть контракта, поле уходит клиенту в `ctx`
   HTTP-ответа. См. "Разрешение конфликта с правилом ошибок" ниже.
   ```python
   with pytest.raises(LoanNotFound) as exc_info:
       loans.get_by_id(999)
   assert exc_info.value.id == 999
   ```
2. **Проверка итогового состояния.** Мутант `limit=3 -> limit=4` в `Membership`
   убивается сценарием на границе лимита: читатель с лимитом выдач на 1 меньше
   требуемого должен получать отказ. Ищи данные, которые различают исходную
   и мутированную ветку, а не повторяй уже покрытые сценарии.
3. **Проверка комбинаций критериев.** Мутации в критериях (`&`, `|`, `~`,
   границы дат) убиваются сценариями с несколькими объектами, из которых
   под условие подходит ровно один: активная выдача другого читателя,
   возвращённая выдача этого читателя, просроченная и возвращённая вместе.
4. **Проверка аргументов, попадающих наружу.** Если аргумент становится частью
   сохранённого агрегата или результата usecase - проверяй его в результате
   (`saved.copies[0].inventory_number == 'INV-2'`), а не факт вызова.

## Эквивалентные мутанты
Мутант эквивалентен, если его нельзя отличить никаким тестом, потому что
поведение не изменилось. Их не убивают тестами - их исключают.

- **`typing.cast` - запретный паттерн для id.** Мутант `cast(int, x)` →
  `cast(None, x)` неубиваем: cast - no-op во время выполнения. Для сужения
  типа id после `save` используется явный helper с проверкой, а не cast:
  ```python
  # app/commands/saved.py
  def saved_id(value: int | None) -> int:
      """id после save: репозиторий обязан выдать идентификатор"""
      if value is None:
          raise EntityNotSaved
      return value


  # в usecase
  return saved_id(self.readers.save(reader).id)
  ```
- **Тексты `__str__` ошибок.** Текст сообщения - не контракт: клиент различает
  ошибки по типу и `ctx` (см. "Ошибки" в `python-classic-architecture`).
  Мутации строк в `__str__` эквивалентны и не закрываются тестами на текст.
- **Тексты логов.** Сообщения логов - служебные, не контракт. Мутации строк
  логов эквивалентны.
- Для исключения мутаций используется прагма mutmut - точечно, с комментарием:
  ```python
  def __str__(self) -> str:  # pragma: no mutate block
      # текст сообщения - не контракт, ошибки различаются по типу
      return f'Выдача с id={self.id} не найдена'
  ```
  `# pragma: no mutate` в конце строки исключает одну инструкцию,
  `# pragma: no mutate block` - весь блок (функцию, метод).
  Прагма без причины не ставится: сначала тест, прагма - только на
  доказуемо эквивалентного мутанта.
- **Запрет на обход правил ради убийства мутантов.** Не проверять тексты
  ошибок и логов в тестах, не проверять факт и аргументы вызовов заглушек,
  не читать приватные поля. Если мутант выживает, а тест, который его убивает,
  нарушает правила тестирования - мутант эквивалентен, ставится прагма.

## Разрешение конфликта с правилом ошибок
Правило "ошибки проверяются по типу, а не по тексту" сохраняется полностью.
Уточнение для мутационного тестирования:
- **тип ошибки** - проверяется всегда (обязательная часть теста);
- **поля ошибки (`ctx`)** - проверяются всегда: они часть контракта,
  попадают в HTTP-ответ клиенту и в `__str__`;
- **текст (`msg`)** - не проверяется: человекочитаемый, меняется свободно,
  мутации текста закрываются прагмой, а не тестом.
Таким образом тест ошибки имеет вид:
```python
with pytest.raises(LoanNotFound) as exc_info:
    ...
assert exc_info.value.id == 999          # ctx - контракт, убивает мутантов id=None
```

## Не мутируется
- Строки `__str__` ошибок и логов - через прагму (текст не контракт).
- `typing.cast` - заменяется на явные проверки (`saved_id`), прагма не нужна.
- Адаптеры (`interfaces`, `infra`, `integrations`), композит - фильтром
  `only_mutate`, мутации там не гоняются.
- Дополнительное сокращение объёма - конфигом: `do_not_mutate` (глобы файлов)
  и `do_not_mutate_patterns` (regex по строкам). `mutate_only_covered_lines`
  (мутировать только покрытые строки, нужен пакет `coverage`) в этой
  архитектуре почти не даёт выгоды: mutmut и так не запускает мутантов функций,
  у которых нет ассоциированных тестов, а unit-тесты app стремятся к полному
  покрытию слоя.
