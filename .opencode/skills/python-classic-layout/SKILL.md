# Python "Classic" Architecture

## Описание

В этом навыке описывается layout проекта на Python, соответствующий шаблону "Классической" архитектуры.

## Когда использовать
- Когда пользователь запрашивает ревью архитектуры.
- Во время разработки новых фич в Python-приложении.жд

## Instructions
- В корне проекта должен быть pyproject.toml.
- Приложение должно быть представлено namespaced Python-пакетом. Пакет должен лежать в src.
- Весь пакет состоит из namespace, ни одного файла __init__.py быть не должно.
- Все импорты должны быть абсолютными.
- Все классы принимают зависимости через конструктор.
- Нужно стремиться к выносу большинства классов в один файл. Можно оставлять в одном файле тесно связанные классы, которые друг без друга не используются, например, UseCase и DTO для этого UseCase.
- Весь код делится на слои. Нижние ничего не знают о верхних, верхние знают о нижних.
  Внизу слой app (приложение), над ним слой адаптеров, над ним - композит.
- Слой приложения делится на 2 группы - запросы (queries) и команды (commands). Запросы и команды НЕ ДОЛЖНЫ знать ничего друг о друге. На слое приложения нужно свести к минимуму использование сторонних библиотек, и оставить на это слое бизнес-логику. Инфрастуктурные моменты должны быть вынесены в адаптеры.
- Слой адаптеров содержит в себе код, обращающийся к приложению, например, HTTP API, и код, обслуживающий запросы приложения, например, адаптер к БД, к файловому хранилищу, к почтовому серверу и т.д. На этом слое можно использовать сторонние библиотеки.
- Слой композит - это точки входа в приложение. Здесь находится инстанцирование нужных классов, передача инстансов друг другу для удовлетворения зависимостей. Каждый инстанс должен находиться в своем файле. В целом этот слой зачастую зеркалит структуру других слоев.
