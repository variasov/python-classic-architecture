# Retrying Aspect in "Classic" Architecture

## Описание

В этом навыке описывается аспект повторов: повторный вызов метода при временной ошибке.
Общие правила аспектов и порядок обёрток описаны в навыке `python-classic-composite`.

## Когда использовать
- При подключении клиента внешней системы или другого вызова, который может временно отказать.
- При написании тестов композита на повторы.

## Instructions

### Назначение
- Повторы - аспект, навешанный в композите на метод, вызов которого может временно отказать: метод клиента интеграции, обращение к сетевому хранилищу, команду, которая может упасть на конфликте транзакций. Сам класс о повторах не знает.
- Повторы выполняются библиотекой tenacity.

### Навешивание
- `tenacity.retry(...)` применяется напрямую в каждом месте навешивания, со своими параметрами. Общий преднастроенный декоратор и файл в `composites/aspects/` не заводятся: параметры повторов - свойство конкретного вызова (какие ошибки у него временные, сколько он стоит, сколько готов ждать вызывающий), и при чтении композита они видны там же, где навешан аспект.
- Параметры указываются явно каждый раз:
  - `retry=tenacity.retry_if_exception_type(...)` - только временные ошибки этого вызова (недоступность внешней системы, сетевые сбои, конфликт сериализации). Ошибки приложения, домена, валидации и авторизации не повторяются: повтор не изменит результат;
  - `stop=tenacity.stop_after_attempt(n)` - число попыток;
  - `wait=tenacity.wait_exponential(...)` - пауза между попытками;
  - `reraise=True` - после последней попытки пробрасывается исходное исключение, а не `tenacity.RetryError`: обработчики ошибок адаптеров продолжают его распознавать.
  ```python
  # composites/integrations/isbn_catalog/client.py
  isbn_catalog_client = IsbnCatalogClient(settings=isbn_catalog_settings)
  isbn_catalog_client.find = tenacity.retry(  # pyright: ignore[reportAttributeAccessIssue]
      retry=tenacity.retry_if_exception_type(IsbnCatalogUnavailable),
      stop=tenacity.stop_after_attempt(3),
      wait=tenacity.wait_exponential(multiplier=0.1, max=2),
      reraise=True,
  )(isbn_catalog_client.find)
  ```
- Повторяются только операции, которые безопасно выполнить ещё раз: чтения и идемпотентные запросы во внешние системы, транзакционные операции. Неидемпотентный вызов внешней системы (отправка письма, платёж) повторяется, только если внешняя система поддерживает ключ идемпотентности.

### Повторы и транзакции
- Повторы оборачивают транзакцию снаружи: каждая попытка выполняется в новой транзакции. Повтор внутри открытой транзакции после ошибки БД невозможен - транзакция уже прервана.
- Порядок с другими обёртками и форматирование нескольких обёрток - в `python-classic-composite`.

## Тестирование
- Повторы не проверяются в unit-тестах классов: классы о них не знают.
- Тесты композита проверяют, что аспект навешан: stub-сервер внешней системы сначала отвечает временной ошибкой, затем успехом - вызов через точку входа завершается успешно. Отдельно - что ошибка, не входящая в `retry=`, не повторяется (stub-сервер получил один запрос).
